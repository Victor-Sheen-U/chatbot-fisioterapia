FASTAPI · PASO 1

Crear la aplicación y una ruta

Primero creamos la aplicación con FastAPI(). Luego definimos una ruta con @app.get. Cuando abrimos esa dirección, FastAPI ejecuta la función y nos devuelve el diccionario como JSON.

from fastapi import FastAPI

app = FastAPI()

@app.get("/api/saludo")
def saludo():
    return {"mensaje": "La API está funcionando"}

Busquen un decorador @app.get en su propio main.py. ¿Qué función se ejecuta al llamar esa ruta?

FASTAPI · PASO 2

Leer los servicios del negocio

Ahora leemos los servicios desde negocio.json. No escribimos el precio dentro de la ruta: lo tomamos del archivo. Si cambiamos el JSON y repetimos la consulta, veremos el precio actualizado.

def negocio():
    return json.loads(
        (BASE / "negocio.json").read_text(
            encoding="utf-8-sig"
        )
    )

@app.get("/api/servicios")
def servicios():
    return negocio()["servicios"]

FASTAPI · PASO 3

Recibir parámetros y calcular disponibilidad

En esta ruta enviamos fecha y servicio en la URL. FastAPI comprueba el formato de la fecha. Nosotros revisamos las reservas activas y quitamos los horarios que ya están ocupados.

@app.get("/api/disponibilidad")
def disponibilidad(fecha: date, servicio: str):
    if servicio not in negocio()["servicios"]:
        raise HTTPException(404, "Servicio desconocido")
    # Filtrar horarios según fecha y reservas...

Si consultamos un domingo, la lista de horas debe quedar vacía.

FASTAPI · PASO 4

Validar el cuerpo con Pydantic

Para crear una reserva usamos POST. Los datos van en el cuerpo de la petición. Con ReservaNueva decimos qué campos deben llegar; si falta alguno, FastAPI responde con un error antes de intentar guardar.

class ReservaNueva(BaseModel):
    cliente: str = Field(min_length=2)
    servicio: str
    fecha: date
    hora: str
    confirmada: bool

Además de validar los campos, tenemos que comprobar que la persona confirmó y que la hora sigue libre.

FASTAPI · PASO 5

Crear y guardar una reserva

Si la reserva está confirmada y la hora está libre, generamos un código y escribimos el registro en reservas_demo.json. El 201 nos indica que la API creó una reserva nueva.

@app.post("/api/reservas", status_code=201)
def crear_reserva(datos: ReservaNueva):
    if not datos.confirmada:
        raise HTTPException(400, "Debe confirmar")
    # Comprobar disponibilidad...
    registros.append(reserva)
    guardar_reservas(registros)
    return reserva

Aquí voy a abrir el JSON para comprobar que el código sí quedó guardado.

FASTAPI · PASO 6

Consultar una reserva por su código

El {codigo} de la ruta es el identificador que acabamos de recibir. Lo usamos para buscar la reserva en el archivo. Si escribimos un código que no existe, la API devuelve 404.

@app.get("/api/reservas/{codigo}")
def consultar_reserva(codigo: str):
    for reserva in leer_reservas():
        if reserva["codigo"] == codigo:
            return reserva
    raise HTTPException(404, "Reserva no encontrada")

FASTAPI · PASO 7

Modificar la reserva

Antes de cambiarla, buscamos la reserva por su código y comprobamos que siga activa. Después validamos la nueva hora, actualizamos el registro y guardamos otra vez el JSON. El código de la reserva no cambia.

class CambioReserva(BaseModel):
    servicio: str
    fecha: date
    hora: str

@app.put("/api/reservas/{codigo}")
def modificar_reserva(codigo: str, datos: CambioReserva):
    # Buscar, validar la nueva hora y guardar...
    reserva.update(
        servicio=datos.servicio,
        fecha=datos.fecha.isoformat(),
        hora=datos.hora
    )
    guardar_reservas(registros)
    return reserva

Comparen la hora nueva con la que apareció al crearla. Abriré el JSON para comprobar el cambio.

FASTAPI · PASO 8

Cancelar y comprobar el estado

Por último, cancelamos la reserva. No borramos el registro: cambiamos su estado a cancelada y guardamos el archivo. Esa hora vuelve a estar disponible.

@app.delete("/api/reservas/{codigo}")
def cancelar_reserva(codigo: str):
    registros = leer_reservas()
    # Buscar y cambiar el estado...
    reserva["estado"] = "cancelada"
    guardar_reservas(registros)
    return reserva

Si volvemos a consultarla, veremos el estado cancelada.

Ahora Python conectará las dos API

El archivo consulta_llm.py será la lógica del chatbot. Recibirá lo que escribe la persona, pedirá a Groq que identifique la intención y llamará a la ruta correspondiente de la FastAPI que ya construyeron. Más adelante Gradio pondrá una interfaz sobre estas funciones.

Groq

Interpreta la solicitud y devuelve datos estructurados. No guarda reservas.

FastAPI

Consulta servicios y disponibilidad; valida, crea, modifica o cancela reservas en el almacenamiento del equipo.

CLIENTE PYTHON · FUNDAMENTO 1

Una petición HTTP tiene partes

Cuando un programa llama a una API, indica una dirección, un método y, cuando corresponde, datos para procesar. GET consulta; POST envía datos para crear o procesar. Los encabezados describen el formato o llevan la credencial.

GET  /api/servicios
POST /api/reservas

POST https://api.groq.com/openai/v1/chat/completions
Authorization: Bearer CLAVE
Content-Type: application/json

Aquí los datos vienen de FastAPI. El cliente no abre el JSON por su cuenta.

CLIENTE PYTHON · FUNDAMENTO 2

¿Qué es el payload?

Payload significa «carga útil»: son los datos que enviamos en el cuerpo de una petición. En Python los armamos como un diccionario. Antes de enviarlos, json.dumps() los convierte en texto JSON y encode("utf-8") en bytes. La URL y la API key van por separado.

payload = {
    "model": modelo,
    "messages": [
        {"role": "system", "content": INSTRUCCIONES},
        {"role": "user", "content": pregunta},
    ],
    "stream": False,
}

model elige el modelo; messages contiene los mensajes; stream: false pide la respuesta completa.

CLIENTE PYTHON · FUNDAMENTO 3

¿Para qué sirven system y user?

system

Indica la tarea y el formato esperado. Aquí pedimos que Groq identifique una acción y devuelva un objeto JSON. Los datos que no aparezcan en la pregunta deben quedar vacíos.

user

Contiene lo que acaba de pedir la persona: «¿Qué servicios tienen?» o «Quiero cambiar mi reserva». En esta clase enviamos una solicitud a la vez; todavía no añadimos mensajes anteriores.

Los roles organizan los mensajes al modelo. No son rutas de FastAPI ni campos que se guarden en reservas.json.

CLIENTE PYTHON · FUNDAMENTO 4

Enviar la petición a Groq

Con Request juntamos la dirección de Groq, el método POST, los encabezados y el payload convertido a JSON. La API key va en Authorization; no va en la pregunta ni en el cuerpo.

Request(
  GROQ_URL,
  data=json.dumps(payload).encode("utf-8"),
  headers={
    "Authorization": f"Bearer {clave}",
    "Content-Type": "application/json"
  },
  method="POST"
)

Antes de probar

Necesitamos una API key de Groq y el ID de un modelo habilitado en la cuenta. Guardamos la clave fuera del código. Si hay un error, miraremos primero el código HTTP: una clave incorrecta no se corrige cambiando el prompt.

CLIENTE PYTHON · FUNDAMENTO 5

La respuesta del modelo es un plan

Groq devuelve un JSON de respuesta. Dentro de choices[0].message.content pedimos otro JSON más pequeño: la acción y los datos que logró identificar. Python lo lee con json.loads() y comprueba que la acción esté permitida.

{
  "accion": "modificar",
  "codigo": "A1B2C3D4",
  "servicio": "corte",
  "fecha": "2026-09-28",
  "hora": "10:00"
}

Un plan todavía no es una reserva

El modelo puede equivocarse o dejar datos incompletos. Python revisa los campos y, si se va a crear, modificar o cancelar, pide confirmación a la persona. Solo después llama a FastAPI.

CLIENTE PYTHON · FUNDAMENTO 6

Python llama la ruta de FastAPI

Con la acción validada, el programa elige la ruta: GET /api/servicios, GET /api/disponibilidad, POST /api/reservas, PUT /api/reservas/{codigo} o DELETE /api/reservas/{codigo}. FastAPI vuelve a comprobar las reglas y guarda el resultado.

Quién decide qué pedir

Groq interpreta la frase. Python acepta solo las acciones previstas y prepara la petición HTTP.

Quién decide si es válido

FastAPI verifica servicios, fechas, horarios y estados. El modelo nunca escribe directamente el JSON.

¿Qué comprobamos al terminar?

Groq interpretó

Identificó una acción y algunos datos. Eso es una propuesta, no una operación ejecutada.

FastAPI ejecutó

Respondió a la petición de Python y, cuando correspondía, cambió una reserva. Comprobamos el código y el registro guardado.
